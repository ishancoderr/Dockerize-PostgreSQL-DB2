# Dockerize-PostgreSQL-DB2 — Agent-2's database

A PostGIS 18 image holding **`agent_2_db`**, the part of the German states
data that [Agent-002](https://github.com/ishancoderr/Agent-002) owns. Agent-1's
database is the sister repository
[Dockerize-PostgreSQL-DB1](https://github.com/ishancoderr/Dockerize-PostgreSQL-DB1).
Each agent can reach only its own database; what it lacks it gets from the
other agent over KQML.

## What gets loaded

On the first start (empty data volume) the init scripts run in order:

| Script | |
|---|---|
| `10_postgis.sh` | from the `postgis/postgis` image: enables PostGIS |
| `init/20_agent2_data.sql` | Agent-2's data, generated by [germany-demographics-births-marriages](https://github.com/ishancoderr/germany-demographics-births-marriages) (`agent2_postgis_db.sql`, commit `257c186`) |

Unlike Agent-1, Agent-2 holds every geometry — it is the agent that supplies
Berlin's polygon and the city points Agent-1 lacks.

Tables:

| Table | Rows | |
|---|---|---|
| `states` | 16 | all federal states with their polygons (EPSG:4326) |
| `state_demographics` | 160 | population, live births, marriages: 10 states, 2010–2025, with deliberate gaps (see `split_metadata.json` in the data repository) |
| `cities` | 1,782 | German cities as points (EPSG:4326) |

The result is identical, row for row, to the `agent_2_db` the agents were
developed and evaluated against.

## Use

**In the deployment** — `kqml-deploy` builds this repository as service `db2`,
reachable only by Agent-2, with the password from its `.env`. Nothing to do
here.

**On its own** (Docker Desktop):

```bash
copy .env.example .env        # set POSTGRES_PASSWORD
docker compose up -d
docker compose ps             # "healthy" once the data is loaded (about 15 s)
docker compose exec db psql -U postgres -d agent_2_db -c "\dt"
```

Connect with `localhost:5435`, database `agent_2_db`, user `postgres`.

Reload from scratch (deletes this container's data): `docker compose down -v`,
then `docker compose up -d`.

## Updating the data

Regenerate `agent2_postgis_db.sql` in the data repository, copy it over
`init/20_agent2_data.sql` (keep LF line endings), update the commit above, and
rebuild. The data only loads into an empty volume, so on a running system the
database volume has to be removed first.
